# 概念学习资料生成技能（concept-learning-generator）

## 一、适用场景

**使用本技能，当：**
- 用户给出一个 AI 概念名称，要求生成学习资料 / 讲解笔记
- 用户说"教我 XX"、"我想搞懂 XX"、"给 XX 做一份学习资料"
- 用户在学习计划中列出某个 AI 概念，需要结构化材料支撑

**不使用本技能，当：**
- 用户要求写代码实现该概念（转开发任务）
- 用户要求对比多个概念的完整选型报告（超过单概念范围时先确认是否拆分）

## 二、输入

| 输入项 | 说明 | 缺省处理 |
|---|---|---|
| 概念名称 | 任意一个 AI 概念，中英文均可 | 必填，缺失则询问 |
| 学习者水平 | 入门 / 有基础 / 进阶 | 默认"有基础"（有编程经验但未系统学过该概念） |
| 学习目的 | 面试 / 科研 / 工程应用 / 通识 | 默认"工程应用" |
| 输出语言 | 中文 / 英文 / 双语 | 默认中文（术语保留英文原文） |

## 三、生成步骤

1. **概念确认与定界**：确认概念的标准英文名与中文译名，划清本概念与相邻概念的边界（如 "RAG" 需区分检索增强生成整体范式与具体框架）
2. **资料检索**：按第五节来源要求检索原始论文、官方文档、权威解读，记录每条来源的标题、作者/机构、链接、访问日期
3. **撰写八个输出模块**：严格按第四节的结构与写作要求逐一撰写
4. **自检**：逐项过第六节自检清单，不合格的模块重写
5. **落盘**：保存为 `learning-materials/学习资料_<概念名>.md`，并向用户报告文件路径与一句话内容概览

## 四、输出结构（八个模块，缺一不可）

生成的学习资料必须包含以下八个模块，顺序固定：

### 模块 1：概念个人解释
- 用自己的话（第一人称"我"）+ 一个生活化比喻解释该概念是什么
- 比喻后必须跟一句"对应关系说明"：比喻的每个部分映射到概念的哪部分
- 禁止直接复制论文摘要式行话；目标读者读完后能向别人复述

### 模块 2：核心机制组成
- 拆解概念的组成部分（输入/输出/核心组件/运行流程）
- 用一个流程图（Mermaid 代码块）或编号步骤描述工作过程
- 每个组件标注：作用、输入输出、为什么需要它

### 模块 3：应用场景
- 列 3–5 个真实应用场景，每个标注：实际产品或研究项目名 + 它如何使用该概念
- 至少 1 个来自中文互联网产品的公开实践（如有）
- 结尾一句：这个概念"不适合"的场景（反例边界）

### 模块 4：易混淆边界
- 给出 2–3 组与本概念最易混淆的相邻概念（如 RAG vs 微调 vs 长上下文）
- 每组用对比表：差异维度 / 本概念 / 易混概念
- 给出 1 个"判断口诀"：遇到什么信号时应该选本概念而不是易混概念

### 模块 5：参考来源
- 列出步骤 2 收集的全部资料，格式：`[标题] — [作者/机构] — [链接] — [访问日期] — [一句话说明该来源讲了什么]`
- 按权威度排序：原始论文 > 官方文档 > 权威团队博客 > 教程

### 模块 6：学习目标
- 写 3–5 条可检验的学习目标，动词开头（能解释/能画出/能判断/能实现）
- 每条标注对应的检验方式：对应到模块 7 的思考题或模块 8 的自测题编号

### 模块 7：核心思考题
- 2–3 个开放式、无标准答案的深度问题
- 每题附"思考提示"（1–2 句，指明思考方向但不给答案）
- 问题应触及概念的局限性、权衡取舍或前沿争议

### 模块 8：自测问题
- 5–8 个有明确答案的自测题，题型混合：概念辨析、判断改错、简答
- 每题附答案与一句解析；解析须与模块 2/4 的内容自洽
- 难度梯度：前 1/3 基础识记，中间理解应用，最后 1–2 题接近面试/科研深度

## 五、资料来源要求

1. **优先级**：原始论文（arXiv/会议官网）> 官方文档与官方博客 > 顶会/名企研究团队公开分享 > 高质量教材与教程
2. **真实性红线**：禁止编造论文标题、作者、链接；链接必须真实可达；无法核实的内容明确标注"未核实"
3. **时效性**：优先近 3 年资料；概念迭代快的（如 Agent 框架）须注明"该领域变化快，以最新官方文档为准"
4. **数量下限**：每份学习资料至少 4 条来源，其中至少 1 条原始论文或官方文档
5. **中文补充**：可引用中文权威社区（如官方中文文档、知名技术社区精华帖），但不得以中文二手翻译替代原始论文

## 六、自检项（交付前逐项打勾）

- [ ] 八个模块全部存在，顺序与第四节一致
- [ ] 模块 1 的比喻附有对应关系说明，无论文腔行话堆砌
- [ ] 模块 2 含流程图或编号流程，组件均有"为什么需要它"
- [ ] 模块 3 有真实产品名，且有"不适合的场景"反例
- [ ] 模块 4 至少 2 组易混概念对比 + 1 个判断口诀
- [ ] 模块 5 来源 ≥ 4 条且含原始论文或官方文档，链接真实
- [ ] 模块 6 学习目标与模块 7/8 的题目编号互相引用
- [ ] 模块 8 全部题目附答案，难度有梯度
- [ ] 文件已保存为 `learning-materials/学习资料_<概念名>.md`
- [ ] 全程未在 C 盘创建任何文件（用户约定）

## 七、示例调用

> 用户："给我生成一份 RAG 的学习资料，我准备面试。"
> 本技能动作：确认水平=进阶、目的=面试 → 检索 Lewis et al. 2020 原论文 + 主流框架官方文档 → 按 8 模块撰写（易混淆边界选 RAG vs 微调 vs 长上下文）→ 自检 → 保存 `learning-materials/学习资料_RAG.md` → 报告路径。
